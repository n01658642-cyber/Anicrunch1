Anilili · UI proposal

Popup, dialog & settings redesign

Every popup currently ships its own container: five corner radii, three title styles, four footer layouts, and the download dialog buries its only hard numbers in a run-on sentence. Settings has the same disease one level down: eleven sections, three row types, essays in 10sp gray. This mock defines one dialog system — same header, same sections, same footer everywhere — re-lays-out the download sheet around its actual data, and rebuilds Settings on grouped cards whose choice rows open the very same sheet. Phones get bottom sheets; TV gets the same content in centered cards that are fully D-pad-driven.

Focus ring: 3dp accent ring + soft halo + 5% scale — visible at 3 m on any surface. Selected is a value, focused is a cursor; the two combine instead of replacing each other. Focusable height on TV is ≥ 48dp. The storage card is informational — it never takes focus, so D-pad skips straight from chips to the primary action.

6 · The system behind it

One set of rules every popup obeys. Implemented once as shared composables, then adopted dialog by dialog.

RuleSpec
Container Phone: bottom sheet, 24dp top radius, scrim. TV: centered card, 20dp radius, hairline border, max 440–620dp. No more stock AlertDialog for anything user-facing.
Header Title titleLarge/800 + one subtitle line (context: series · episode · count). Optional close chip top-right (TV). Nothing else above the fold.
Sections labelMedium, uppercase, tracked, dim — never bold body text as a pseudo-header. One helper line max per section, labelSmall dim.
Data Numbers get a designed home (storage summary card: size, scope, free/after, proportion bar). Never a run-on sentence.
Warnings Callout: tinted 12dp container + leading icon, amber for caution, red for blocked, accent for info. Never naked red labelSmall text.
Footer Exactly one primary filled action (states what happens: "Download 12 episodes"). Cancel as quiet text right-aligned. Destructive as red text bottom-left, separated from Cancel — or a filled red button in confirmations.
Focus (D-pad) Open with focus on the current selection, or the primary action when there is none. Traversal: Down/Up across sections, Left/Right within a row, informational blocks never take focus, destructive always sits after the primary in traversal order. Back dismisses unconditionally (unless an action is in flight). Ring: 3dp accent + halo + 5% scale; focusable height ≥ 48dp on TV.
Settings Rows grouped in 14dp surface cards under uppercase section labels. A row is: tinted icon · title · ONE-line description · switch / value chip / status, plus chevron when it opens something. Full explainers live in the picker, never on the row. Danger actions grouped last with red icon containers. Collapsible sections stay (D-pad friendly), with a summary line when collapsed.
Copy Explainers cut to one line each. The "rewrapped into one MP4" essay becomes "Device copies land in Downloads/Anilili as MP4 with subtitles."

7 · Rollout order

Each step is one self-contained commit. Every step builds and is D-pad-walked on both emulators (anilili_phone and anilili_tv) before it lands.

StepScope
1Shared building blocks: AnililiSheet (phone) + AnililiCardDialog (TV) containers sharing one content slot, section label, callout, storage summary, footer row, and the focus-ring modifier.
2Download dialog rebuild (the one that motivated this).
3Unify My List + Continue Watching onto one status-card component and footer.
4Removal confirmations (episode / all) → centered card with filled danger button.
5Update dialog states → same card; CaptionAppearance + OpenSubtitles account dialog pass.
6Settings rows: grouped card containers, the four row components, one-line descriptions, callout feedback, cache storage card, regrouped sections.
7Choice pickers (quality, audio, UI scale, watched-at, skip length, server priority, menu language, download destination) move into the step-1 hosts — sheet on phone, centered card on TV, initial focus on the current value.
